# onec-nix — 1С:Предприятие 8.3 для Nix / NixOS

onec-nix — Nix-пакет и NixOS-модуль для платформы «1С:Предприятие 8.3»:
клиент, сервер (ragent), RAS, учебная версия.

> **Дистрибутива 1С здесь нет и не будет.** Каждый пользователь скачивает
> архив сам, со своего аккаунта на [releases.1c.ru](https://releases.1c.ru)
> (учебную версию — с сайта 1С), и добавляет его в свой `/nix/store`.
> Не публикуйте ни архив, ни собранный из него пакет (в том числе в публичных
> бинарных кэшах вроде Cachix). Подробнее — в разделе «Лицензирование».

## Требования

- `x86_64-linux`;
- Nix с включёнными flakes (`experimental-features = nix-command flakes`);
- NixOS — для системного модуля (`nixosModules.default`). Без NixOS пакет
  собирается через `lib.mkOnec`, см. «Без NixOS-модуля».

## Быстрый старт

1. Скачайте «Технологическая платформа 1С:Предприятия (64-bit) для Linux»
   или учебную версию.
2. Положите архив в стор и узнайте хеш:

   ```sh
   nix store add --mode flat ~/Downloads/server64_8_3_27_2130.tar.gz
   nix hash file ~/Downloads/server64_8_3_27_2130.tar.gz
   ```

   `--mode flat` обязателен: `pkgs.requireFile` ждёт хеш самого файла, а
   `nix store add` по умолчанию добавляет файл как NAR — путь не совпадёт.
   (Старая `nix store add-file` делает то же, что `--mode flat`, но помечена
   устаревшей.)

3. Подключите флейк:

   ```nix
   {
     inputs = {
       nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
       onec.url = "github:Shturmill/onec-nix";
       onec.inputs.nixpkgs.follows = "nixpkgs";
     };

     outputs = { nixpkgs, onec, ... }: {
       nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
         system = "x86_64-linux";
         modules = [
           onec.nixosModules.default
           ({ pkgs, ... }: {
             nixpkgs.config.allowUnfree = true;

             services.onec = {
               enable = true;
               src = onec.lib.requireDist pkgs {
                 name = "server64_8_3_27_2130.tar.gz";
                 hash = "sha256-…"; # из `nix hash file`
               };
               client.enable = true;
               licensesDir.users = [ "alice" ]; # кто активирует лицензию
             };
           })
         ];
       };
     };
   }
   ```

4. Примените конфигурацию:

   ```sh
   sudo nixos-rebuild switch --flake .#myhost
   ```

   `myhost` — имя вашей конфигурации из `nixosConfigurations` (обычно совпадает
   с именем машины). В меню появятся «1С:Предприятие», тонкий клиент и
   Конфигуратор.

> После `nix-collect-garbage` архив из стора удаляется. Пока пакет собран, это
> ни на что не влияет; если понадобится пересборка (обновили nixpkgs), сборка
> остановится с подсказкой — повторите `nix store add --mode flat`.

## Совместимость

| Версия 1С | Дистрибутив | Клиент (тонкий / толстый, Конфигуратор) | Сервер (ragent, RAS) |
| --- | --- | --- | --- |
| 8.3.27.1508 | учебная (`training_*_LinuxRun.tar.gz`) | ✅ проверен | — нет в дистрибутиве |
| 8.3.27.2130 | `server64_*.tar.gz` | требует подтверждения | требует подтверждения |
| до 8.3.18 (напр. 8.3.12) | архивы с `.deb` | только распаковка (тесты на фальшивом архиве) | не проверялся |

✅ — прошла интеграционная проверка на настоящем дистрибутиве
(`tests/run-integration.sh`). Проверили другую версию — пришлите PR с
обновлением таблицы.

Поддерживаемые форматы: `.tar.gz`, `.zip`, голый `setup-*.run`, старые
архивы с `.deb` (раскладка `/opt/1C/v8.3`). Версия определяется по имени файла
(`server64_8_3_27_2130.tar.gz` → `8.3.27.2130`), учебная версия — по слову
`training` (`training_8_3_27_1508_LinuxRun.tar.gz` → `/opt/1cv8t`).

## Использование

### Учебная версия

```nix
services.onec = {
  enable = true;
  src = onec.lib.requireDist pkgs {
    name = "training_8_3_27_1508_LinuxRun.tar.gz";
    hash = "sha256-…";
  };
  client.enable = true;
};
```

Ставится в `/opt/1cv8t`, бинарники — `1cestartt`, `1cv8t` (толстый клиент /
Конфигуратор), `1cv8ct` (тонкий клиент). `optName` определяется по имени
файла сам. В учебном дистрибутиве есть только `client_full`, `ws` и языки:
`server.enable`/`ras.enable` с ним отклоняются при вычислении конфигурации.

### Сервер

```nix
services.onec = {
  enable = true;
  src = …;
  server = {
    enable = true;          # systemd: 1c-ragent.service, пользователь usr1cv8
    openFirewall = true;    # 1540, 1541, 1560–1591
    # dataDir = "/var/lib/1cv8"; port = 1540; regport = 1541; range = "1560:1591";
  };
  ras.enable = true;        # 1c-ras.service на 1545, для rac и консолей
};
```

Нужные компоненты инсталлятора (`server`, `server_admin`, `client_full`)
модуль добавляет сам. Свои — через `services.onec.components`; полный список
печатается в логе сборки («onec: компоненты дистрибутива: …»).

### Без NixOS-модуля

```nix
onec.lib.mkOnec pkgs {
  src = onec.lib.requireDist pkgs { name = "…"; hash = "…"; };
  components = [ "client_full" ];   # язык (language, по умолчанию "ru") добавится сам
}
```

Пакет даёт `bin/1cv8c`, `bin/1cestart` и т.д. `1cestart` ищет установленные
версии в `/opt/1cv8` — без модуля (опция `linkToOpt`) пользуйтесь `1cv8c`
напрямую.

### Опции модуля (кратко)

| Опция | По умолчанию | Что делает |
| --- | --- | --- |
| `src` | — | архив дистрибутива (лучше через `requireDist`) |
| `version` | из имени файла | версия платформы |
| `components` / `disabledComponents` | `[ ]` | `--enable-components` / `--disable-components` |
| `language` | `"ru"` | язык интерфейса (добавляется в компоненты) |
| `client.enable` / `client.fonts` | `false` / `true` | клиент в PATH, corefonts для печатных форм |
| `client.scale` | `null` | масштаб интерфейса, дробный: `1.25` = 125 % (`ONEC_SCALE` — на один запуск) |
| `server.*`, `ras.*` | выкл. | сервисы ragent и ras |
| `linkToOpt` | `true` | `/opt/1cv8/x86_64/<версия>`, `common`, `conf/conf.cfg` (для 1cestart, EDT) |
| `optName` | по имени файла | `"1cv8t"` — учебная версия |
| `licensesDir.mode` / `.group` | `"2775"` / `grp1cv8` | права на `/var/1C/licenses` |
| `licensesDir.users` | `[ ]` | кого добавить в группу лицензий |
| `preferWebkit41` | `true` | переключение на `.wk41`-библиотеки |
| `dropBundledLibs` | `[ ]` | удалить бандловые .so (отладка) |
| `extraPkgs` | `_: [ ]` | доп. пакеты в FHS-окружение |

У `mkOnec` есть ещё `autoDisableComponents` (по умолчанию `true`) и
`runtimeProfiles` (`[ "client" ]`, `[ "server" ]` или оба; по умолчанию —
по компонентам).

### Каталог лицензий 1С

`/var/1C/licenses` создаётся с владельцем `root:grp1cv8` и правами `2775`:
писать могут root и члены группы, остальные — только читать (так советует
1С). Бит setgid нужен, чтобы файл лицензии, активированной одним
пользователем, принадлежал группе и оставался доступен остальным. Добавьте
в группу тех, кто активирует лицензии из клиента: `licensesDir.users`.
Аппаратные ключи HASP модуль не настраивает.

## Как это устроено

Сборка в две стадии:

1. **Распаковка** (`pkgs/onec/dist.nix`). Из архива достаётся инсталлятор
   `setup-*.run` и запускается в unattended-режиме внутри bubblewrap.
   Песочница даёт ему то, что он ожидает от обычного дистрибутива Linux:
   root, `/lib64/ld-linux-x86-64.so.2`, `/bin/bash` для postinst-скриптов,
   `ln`/`sed`/`awk` в `PATH` — и подмонтированный каталог сборки как `/opt`
   (инсталлятор и postinst работают с зашитыми путями `/opt/1cv8{,t}`,
   `--prefix` не используется). Хост не затрагивается.
   Перед установкой список компонентов сверяется с `--help` инсталлятора:
   - заказан компонент, которого нет в дистрибутиве, — понятная ошибка;
   - всё, что не заказано, явно отключается (`ws`, лишние языки…) — меньше
     размер (учебная 8.3.27: 1,9 ГБ вместо 2,4 ГБ) и воспроизводимый состав.

   После установки проверяется, что нужные бинарники на месте. Бинарники
   при этом не меняются, правится только поставка:
   - удаляются бандловые `libstdc++.so.6*` / `libgcc_s.so.1` (они старее, чем
     нужно webkitgtk из nixpkgs);
   - WebKit-зависимые библиотеки переключаются на сборку под webkitgtk **4.1**
     (`*.wk41`): ветки 4.0 в nixpkgs больше нет.

   Старые архивы с `.deb` просто распаковываются.
2. **Запуск** (`pkgs/onec/default.nix`). Платформа работает в FHS-окружении
   `buildFHSEnv`, где в `/usr/lib` лежат нужные библиотеки из nixpkgs. Для
   каждого бинарника из поставки (`1cv8c`, `1cv8`, `1cestart`, `ragent`, `rac`…)
   создаётся обёртка в `bin/` (клиентам — с обходами дефектов окон под X11,
   см. «Если не запускается»). Набор библиотек зависит от компонентов
   (`pkgs/onec/runtime-deps.nix`): клиенту — GTK, WebKit, CUPS; серверу —
   только шрифты и растр, без GTK/WebKit/GStreamer.

## Если не запускается

- **Не хватает библиотеки** (`error while loading shared libraries`):
  ```sh
  onec-shell -c 'ldd /opt/1cv8/x86_64/*/1cv8c | grep "not found"'
  ```
  Найдите пакет (`nix-locate libXXX.so`) и добавьте в `extraPkgs`, или пришлите
  PR в `pkgs/onec/runtime-deps.nix`. Без аргументов `onec-shell` открывает bash
  внутри окружения.
- **Падение (SIGSEGV) при открытии форм.** Частая причина — конфликт бандловых
  графических библиотек 1С с библиотеками nixpkgs. Попробуйте убрать их:
  `dropBundledLibs = [ "libcairo-v8.so" ];`
- **Мелкий интерфейс на HiDPI / под Wayland.** 1С работает через XWayland, а
  при `xwayland:force_zero_scaling` (Hyprland) композитор такие окна не
  масштабирует. Задайте `client.scale = 1.25;` или запустите разово
  `ONEC_SCALE=1.5 1cv8c`. Масштаб общий для всех мониторов.
- **Серые полосы после fullscreen/maximize, долгое закрытие окна**
  (Конфигуратор, толстый клиент под Hyprland и другими WM без рамок).
  Окна 1С на wxWidgets не перестраивают содержимое, если WM за одно
  событие меняет и позицию, и размер окна, а при закрытии 1С ещё ~2 с
  держит окно на экране, дожидаясь своих потоков. Клиентам подгружается
  `LD_PRELOAD`-библиотека (`pkgs/onec/x11-fixes.c`): она делит такое событие
  на перемещение и изменение размера и прячет закрываемое окно, как только
  1С перешла к завершению (если 1С спрашивает «Сохранить изменения?», окно
  остаётся). Бинарники не меняются; отключить — `ONEC_NO_X11_FIXES=1`.
- **Клиент висит при старте без окна** — обычно нет шрифтов. Окружение
  подставляет свой `FONTCONFIG_FILE` (системная конфигурация + шрифты
  окружения); если вы задаёте `FONTCONFIG_FILE` сами, проверьте его.

## Разработка

Проверки (`tests/default.nix`) работают на **фальшивых** архивах, которые
ведут себя как настоящий инсталлятор (нет `--prefix`, зашитые пути `/opt`,
`ln` из `PATH`, postinst на `/bin/bash`, список компонентов в `--help`),
так что CI не нужен настоящий дистрибутив:

```sh
nix flake check      # распаковка, учебная версия, ошибка на отсутствующий
                     # компонент, профили зависимостей, модуль, запуск в FHS
```

Проверке `fhs-run` нужны user namespaces внутри песочницы сборки (на NixOS
есть по умолчанию; в GitHub Actions включаются в `ci.yml`).

### Интеграционная проверка на настоящем дистрибутиве

Только локально, в CI дистрибутиву не место:

```sh
tests/run-integration.sh ~/Downloads/training_8_3_27_1508_LinuxRun.tar.gz
tests/run-integration.sh ~/Downloads/server64_8_3_27_2130.tar.gz client_full server
```

В песочнице сборки (`tests/integration.nix`) проверяется: все исполняемые
ELF находят свои `lib*.so` в FHS-окружении; создаётся файловая ИБ
(`CREATEINFOBASE` под Xvfb); для учебной версии ещё — выгрузка конфигурации
Конфигуратором (`DESIGNER /DumpCfg`), тонкий клиент и `1cestart` работают без
падения.

`flake.lock` зафиксирован: обновляйте nixpkgs осознанно (`nix flake update`)
и прогоняйте интеграционную проверку — платформа чувствительна к версиям
webkitgtk, glibc и GTK.
